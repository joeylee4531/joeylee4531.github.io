앨리스의 게임 가방에 회복 물약 10개, 화살 50개, 한정판 검 1개가 있다. 게임이 아이템 종류마다 ERC-20 컨트랙트를 따로 배포한다면 새 종류를 추가할 때마다 별도 컨트랙트가 필요하다. ERC-721은 한 컬렉션에서 여러 NFT를 관리할 수 있지만 각 ID는 NFT 하나를 가리킨다. ERC-1155는 한 컨트랙트에 여러 종류의 토큰을 두고, 같은 ID 안에서 수량을 관리할 수 있게 한다. ERC-1155를 공부하면 **종류별 잔액을 조회하고 여러 종류의 토큰을 한 번에 보내는 방법**을 알 수 있다. [ERC-1155 제안 배경](https://eips.ethereum.org/EIPS/eip-1155#motivation)

## 같은 컨트랙트에서 아이템 구분하기

회복 물약에 ID 1, 화살에 ID 2, 한정판 검에 ID 3을 배정했다고 하자. `balanceOf(앨리스, 1)`은 앨리스의 물약 잔액인 10을 반환한다. 물약과 화살 잔액을 같이 읽으려면 `balanceOfBatch([앨리스, 앨리스], [1, 2])`를 호출한다. 같은 위치의 주소와 ID가 한 쌍이므로 반환값은 `[10, 50]`이다.

한정판 검을 한 자루만 발행하려면 컨트랙트가 ID 3의 총 발행량을 1개로 제한하도록 구현할 수 있다. 서로 구분해야 하는 검이 두 자루라면 각각 다른 ID를 준다. 같은 ID에 수량을 2로 기록하면 전송 기록에는 그 종류의 검이 몇 자루 움직였는지만 남는다. [잔액 조회 명세](https://eips.ethereum.org/EIPS/eip-1155#specification) · [NFT를 표현하는 방식](https://eips.ethereum.org/EIPS/eip-1155#non-fungible-tokens)

## 물약과 화살을 한 번에 보내기

물약 3개만 보내려면 `safeTransferFrom`을 쓴다. 화살 20개도 같이 보내려면 `safeBatchTransferFrom`에 ID와 수량을 각각 배열로 전달한다. 마지막 인자는 수신 컨트랙트에 전달할 추가 데이터이며, 예시에서는 비워 둔다.

```text
safeBatchTransferFrom(앨리스, 밥, [1, 2], [3, 20], "")
```

**같은 위치의 ID와 수량이 한 쌍**이다. 밥의 잔액이 처음에 0이었다면, 전송이 끝난 뒤 잔액은 다음과 같다.

| 아이템 | 앨리스 전송 전 → 후 | 밥 전송 전 → 후 |
| --- | --- | --- |
| 물약 | 10 → 7 | 0 → 3 |
| 화살 | 50 → 30 | 0 → 20 |
| 한정판 검 | 1 → 1 | 0 → 0 |

화살을 60개 요청하면 앨리스의 잔액이 부족해 호출 전체가 되돌아간다. 물약도 밥에게 넘어가지 않는다. ID 배열과 수량 배열의 길이가 달라도 전송은 실패한다. 여러 종류를 같은 주소에 보낼 때는 일괄 전송으로 별도 트랜잭션을 반복하는 비용을 줄일 수 있다. [일괄 전송 명세](https://eips.ethereum.org/EIPS/eip-1155#specification) · [일괄 전송 사용법](https://eips.ethereum.org/EIPS/eip-1155#batch-transfers)

## 받는 컨트랙트의 응답 확인하기

받는 쪽이 일반 지갑 주소라면 수신 함수가 호출되지 않는다. 게임 보관함처럼 코드가 있는 주소에 보낼 때는 수신 함수를 통해 전송을 받아들이는지 확인한다. 단일 전송에는 `onERC1155Received`를 사용하고, 일괄 전송에는 `onERC1155BatchReceived`로 여러 종류를 함께 전달할 수 있다.

토큰 컨트랙트는 잔액 변경을 반영하고 전송 이벤트를 남긴 뒤 수신 함수를 호출한다. 보관함이 전송을 거절하거나 정해진 응답 값을 반환하지 않으면 **일괄 전송 전체가 되돌아간다.** 갱신했던 잔액과 이벤트 기록도 되돌아간다. [수신 인터페이스와 안전 전송 규칙](https://eips.ethereum.org/EIPS/eip-1155#safe-transfer-rules)

## 마켓에 전송 권한 주기

앨리스가 `setApprovalForAll(마켓, true)`를 호출하면, 마켓은 이 컨트랙트에서 앨리스가 가진 물약·화살·검을 모두 대신 옮길 수 있다. 기본 인터페이스에는 ERC-721의 개별 승인처럼 특정 ID 하나만 승인하는 함수가 따로 없다. 현재 권한은 `isApprovedForAll(앨리스, 마켓)`으로 조회하고, `setApprovalForAll(마켓, false)`로 철회한다. [ERC-1155 승인 규칙](https://eips.ethereum.org/EIPS/eip-1155#approval)

## 지갑은 아이템 정보와 목록을 어떻게 찾을까?

컨트랙트가 선택 메타데이터 확장을 구현했다면 지갑은 `uri(1)`로 물약의 이름·설명·이미지 정보가 담긴 JSON 문서의 위치를 찾을 수 있다. 주소에 `{id}`가 있으면 지갑은 그 부분을 ID에 해당하는 64자리 소문자 16진수로 바꾼다. [메타데이터 명세](https://eips.ethereum.org/EIPS/eip-1155#metadata)

아이템 목록과 잔액 변화를 추적하려면 컨트랙트 배포 시점부터 `TransferSingle`과 `TransferBatch`를 읽을 수 있다. 예를 들어 물약 10개가 앨리스에게 발행된 뒤 3개가 밥에게 넘어갔다면, 탐색기는 발행 기록과 전송 기록을 순서대로 반영해 앨리스 7개, 밥 3개를 계산한다. [이벤트로 목록 만들기](https://eips.ethereum.org/EIPS/eip-1155#enumerating-from-events)

## 실제 구현 사례 · Horizon Games의 일괄 전송

공식 명세는 여러 토큰의 잔액을 한 저장 칸에 묶는 Horizon Games의 공개 구현을 소개한다. 이처럼 여러 잔액이 같은 저장 칸에 들어가는 구현에서는, ID를 정렬해 같은 칸의 잔액을 연달아 처리하면 가스를 줄일 수 있다. 정렬은 표준의 권장 사항이며 절감 효과는 저장 방식에 따라 달라진다.

예를 들어 ID 배열 `[2, 1]`과 수량 배열 `[20, 3]`에서 ID와 수량을 한 쌍으로 묶어 ID가 작은 순서로 배치하면 각각 `[1, 2]`와 `[3, 20]`이 된다. ID만 바꾸면 물약 20개와 화살 3개를 보내라는 뜻으로 달라진다. 이 사례는 공식 명세가 연결한 공개 구현을 기준으로 살펴봤다. [ERC-1155 Batch Transfers](https://eips.ethereum.org/EIPS/eip-1155#batch-transfers)
